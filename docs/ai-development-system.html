O produto que estamos construindo

O guardIAn é, ele mesmo, um portão antes da LLM. Não confunda o hook do produto com os hooks de desenvolvimento.

Prompt no Claude Code→ Hook UserPromptSubmit→ segredo? · <5 palavras?→ JEV: 4 critérios→ 🔴 <50% · 🟡 50–74% · 🟢 ≥75%→ LLM (só se liberado)

Agentes

Só os que se pagam. PO, PM, DBA, SRE e FinOps ficaram de fora: projeto pessoal, SQLite e localhost.

Orchestrator T2

Triagem, decomposição, paralelismo, consolidação, gates e atualização de estado.

Explorer T1

Perguntas factuais com arquivo:linha. Não decide nem edita. Pode rodar em paralelo.

Reporter T1

Relatórios para dev, tech lead, PO ou daily.

Architect T2 T3

Soluções proporcionais e ADRs. Escala para T3 em decisões críticas.

Backend Dev T2

Server, núcleo de avaliação, shared e plugin/hook.

Frontend Dev T2

UI React: abas, colunas, barras, override, playground.

QA T2

Paralelo: QA_REGRAS · QA_API · QA_HOOK · QA_UI · QA_SEGURANCA.

Reviewer T2

Revisão crítica do diff: bugs, regras, segredos, complexidade.

DevOps T2

Tooling, lefthook, GitHub Actions, build e homologação local.

Workflow de uma demanda

O Orquestrador escolhe o fluxo proporcional: uma pergunta factual não passa por arquitetura.

Demanda→Orchestrator→ Explorer→Architect*→ Gate G1*→Developer→ QA→Reviewer→ Reporter→Gate G8→ Commit/Push/PR→Status + Handoff

* somente para mudanças estruturais.

TipoFluxo
Pergunta factualExplorer → resposta
TrivialImplementação → commit
PequenaExploração → Implementação → Testes → Revisão → Commit
MédiaPlanejamento → Implementação → Testes → Revisão → Report → Commit/PR
GrandePlanejamento → Arquitetura + ADR + gate → … → Commit/PR
